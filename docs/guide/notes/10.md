# #10 Run provenance and shared generation

- Set out to: make every run traceable to a commit, and give DPO and eval one generator.
- Found: Part 1's final SFT run came from a dirty tree and recorded no commit (issue #10 body).
- Decision: `summary.json` carries `provenance` (commit, dirty, scratch, versions); a dirty run is marked scratch (`docs/decisions.md`, "Record each run's commit...").
- Review caught provenance being captured after training; fixed with a test that failed before (PR #16 body).
- Batched greedy decoding differs from one-at-a-time: batch size 1 reproduced all 10 saved answers, batch size 5 diverged on 4 of the 5 that hit the limit (PR #16 body; decisions.md "Treat the generation batch size as a setting"; measured, not saved).
- So batch size is recorded as a setting and held fixed across systems.
- Files: `src/post_training/run.py`, `src/post_training/generate.py`, `tests/test_run.py`, `tests/test_generate.py`.
