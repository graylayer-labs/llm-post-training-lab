# #21 Checkpoints and resume

- Set out to: stop a crash late in an SFT run losing everything; the laptop killed a Part 1 run and the GPU is shared (issue #21 body).
- Decision: checkpoint every 25 steps, `lab sft --resume`, refuse to start over checkpoints, require the same commit and config on resume (`docs/decisions.md`, "Checkpoint training runs...").
- Found: the Trainer's own `training_loss` is wrong after a resume, 3.3802 against 4.1598 uninterrupted on a tiny CPU run (PR #22 body). So `train_loss` is the mean of the logged step losses.
- Limit: MPS RNG state is not restored, so a resumed MPS run is statistically equivalent, not bit-identical (decisions.md). A resumed run's wall time and peak memory cover only the resumed part.
- Proof so far: the #12 re-run ran with checkpoints on MPS (`outputs/sft/summary.json`, `save_steps` 25). No MPS kill-and-resume was run after the review fixes (PR #22 body).
- Files: `src/post_training/train/sft.py`, `tests/test_sft_resume.py`, `tests/test_resume_equivalence.py`.
